## paste64：所有輸入框可複製貼上
- 根因：`JS/ui.js`（與根目錄鏡像）的保護層全站攔截 contextmenu（右鍵／長按選單）。Android Chrome 長按輸入框會觸發 contextmenu，被攔掉後就出不來「貼上」；桌機右鍵貼上同樣被擋。部署用的 `obfuscate.js` 也會注入同樣的攔截（capture 階段）。
- 改法：兩處都改成「輸入框、textarea、select、可編輯區（contenteditable）、標了 data-allow-copy 的區塊、以及已經選取的文字」一律放行；圖片、牌面、盤圖等其餘區域照舊擋右鍵另存。快捷鍵保護（F12、Ctrl+Shift+I/J、Ctrl+U/S）未動，Ctrl+C/V/X/A 本來就沒擋。
- 同類一併處理：問題欄長度上限統一提高到 1000 字（八字、梅花、紫微、塔羅、塔羅追問原本 200 或 500 字，貼上長問題會被默默截斷）；ui.js 內三個獨立工具的延遲載入版本號一併更新。
- 新增 `tests/paste-allowed-20261023.cjs`（所有 contextmenu 擋板須放行可編輯元素；不得攔 paste/copy/cut；CSS 不得對 input／body 設 user-select:none）。
- 鏡像修正（自查發現）：根目錄 `bazi.js` 自 focus37 起沒跟 `JS/bazi.js` 同步（網站載入的是 JS/ 版，線上不受影響），以及 `ai-analysis.js`、`ziwei-standalone.js`、`meihua-standalone.js` 根目錄鏡像，已全部同步；scene2 包誤加的根目錄 `liuren-room.js`（原專案沒有此檔）已移除——若已部署請把根目錄那個檔刪掉。新增 `tests/mirror-parity-20261023.cjs`（52 組 JS/ 與根目錄同名檔必須逐位元相同）。
