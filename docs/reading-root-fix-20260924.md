# 2026-09-24 第二輪：把解答流程接到實際出口

這是累積修正版。ZIP 仍以最初提供的 `mytool-blue-master.zip` 為比較基準，只收錄新增或內容改變的檔案；保留相對路徑覆蓋即可，不必先套第一包。網站尚未由本次作業部署。

第一輪完成了盤面與方法指引修正，卻沒有證明外部 AI 實際成稿已達標。你提供的雷諾曼答案清楚顯示：就算提示詞寫了「先回答、完整牌句」，模型仍可能先講鏡像、重複同一組牌，並把象徵錯當成病情。這一輪處理的是這個缺口。

## 如何讓修正可以驗收

| 層次 | 本次落實 | 實際驗收方式 |
| --- | --- | --- |
| 排盤／抽取 | 保留各法原生算法、政策、來源與資料；補回已發現的缺項 | 舊引擎參考案例、邊界測試、全狀態檢查與原資料不變檢查 |
| 資料到提示詞 | 每個入口都帶可覆核依據，最後接上原問題的作答任務 | 執行 14 種方法的真正匯出函式，不用手工拼出的替代提示詞 |
| 解答組織 | 做法、原因、比較、時機、是否及整體題各有不同開頭與落點 | 14 方法 × 6 題型；原問句、子題、方法及尾端連結完整保留 |
| 成稿回看 | 免費本機回看、原盤重答提示詞及命令列介面 | 你提供的失敗案例、人工參考答案、錯誤資料及手機操作 |
| 後續維護 | 共用來源產生各入口備援，版本與快取同步 | 同步檢查；新增方法但未接入作答流程時測試會失敗 |

這裡的「完整」是本專案明列方法與政策下的資料完整、實作可覆核。文獻有流派分歧，不能把「各派所有規則都已收齊」或「命理能準確預測現實」寫成工程測試結論。

## 真正改了哪些內容

1. **新增 `JS/reading-workflow.js`。** 原問題完整保留，在盤面之後產生本題作答任務。方法題直接要求先說能做什麼、怎麼開口；結構題直接找主阻點；比較題使用相同標準；時間題保留原期間及條件。每個方法仍沿自己的牌位、宮位、格局或爻位成判，沒有改成一套共用吉凶算分。
2. **縮短共用成稿指引，保留各法深度。** `reading-quality.js` 的共同口吻改為答案、必要理由、重要牽制、具體行動；完整技法留在方法層供判讀。去除逐項報盤式開場，也不要求每段自報「證據／推論／限制」。
3. **補回人格與姓名依據。** 人格提示詞原先偏重五軸模型摘要，現在附本次八字原局資料；未知時辰只帶三柱。姓名學原先的白話摘要缺少逐字筆畫，現在匯出本次引擎原始結果，包含姓與名的切分政策、筆畫、五格、三才及既有流派候選。
4. **補雷諾曼牌庫一致性。** 匯出前逐張核對牌號、中文名、英文名、核心詞與語義。牌號有效但牌名／牌義遭換置時不再產生看似合法的提示詞；正常匯出不重抽、不改原牌、不增加人物。
5. **修正健康情境的推論次序。** 只有問題明示健康照顧時才加入相應實務資訊。躁鬱症照顧先考慮聯絡治療團隊與現實變化；牌面保留在反思參與方式的層次。「騎士＝迅速消息」不再被提示成躁鬱症快速循環的證據，也不把伴侶的穩定全交給問卜者負責。
6. **新增可選的「解讀回看」。** 首頁頁尾可進入 `reading-review.html`。使用者貼原問題與外部 AI 的答案，本機找出部分已知問題；加入原始提示詞後可產生重答要求，保留原盤。資料不送出、不儲存，也不新增付費 AI 呼叫。
7. **把導購留在解答之後。** 一位佩戴者、一個主設計、一項具體提醒，再自然邀請到賣場。健康案例不以礦物承諾治療。紫微原先在賣場尾行之後還有其他規則，已調整順序；有效解讀保留指定 Markdown 連結及祝福。
8. **同步所有實際入口。** 共用作答版本為 8.0.0、選品版本為 4.6.0、流程模組為 1.0.0。獨立入口內嵌相同備援，根目錄副本同步，頁面載入與歷史版本改為 `20260924root2`，公開站快取改為 v100。

第一輪的酉丑半合、刑名與配對方向、跨盤分層、四化來源及同期運限修正仍包含在這包；詳見 [第一輪紀錄](reading-fix-20260924.md)。第一輪紀錄中的 v99 是歷史版本，本包以 v100 為準。

## 成稿如何驗收

人工逐段確認以下事項，而不是用「有幾個吉星、幾條限制」計分：

- 首段已回答原問題，具體到方向、優先做法或未定的關鍵條件。
- 每個主要結論能追到本次的有效資料；有支持，也有真正改變判斷的反向條件。
- 技法服務答案。移除一段教學後答案完全不變的，應刪掉；移除盤面後仍可套給任何人的，應補上決定性依據。
- 未提供的經歷和心理只作待核對假設；符號不替代醫療、同意或事實查證。
- 行動有做法與觀察點，且與主問題相關；手鍊推薦不改寫主判。

[雙人關係人工參考](reading-example-20260924.md)與[雷諾曼人工參考](reading-lenormand-example-20260924.md)是本次撰寫的口吻與論證樣本，並非外部模型實測回答，也沒有硬編碼成網站對任何人的答案。

`JYReadingWorkflow.review()` 是有限的文字模式檢查。它能抓出本次已知錯誤，**無論有沒有找到問題，都不回傳「命理解讀正確」**；`semanticVerification` 固定為 `not_performed`。真正的全盤取捨、細緻語義及外部模型遵循程度仍需人工覆核。這個功能提供修訂途徑，不能替代原生引擎或假裝完成另一輪占斷。

## 維護與測試

```sh
npm run sync:recommendations
node scripts/sync-recommendation-guides.cjs --check
npm run test:reading-workflow
npm run test:reading-grounding
npm test
```

手機實際表單、複製、下載與回看頁：

```sh
JY_CHROMIUM=/path/to/chromium npm run test:reading:browser
```

CLI 支援 `method`、`question`、`answer`、可選的 `evidence` 與 `sourcePrompt`：

```sh
node scripts/review-reading.cjs < case.json
node scripts/review-reading.cjs --repair < case-with-original-prompt.json
```

完整引擎回歸包含專案既有的紫微參考盤、八字曆法與起運、星曆固定對照、梅花本互變、六爻／易經、蓍草、各牌陣及原籤詩。新增整合測試驗證 14 個實際出口，並核對原資料沒有因提示詞改寫而變動。最終執行結果另列於本包的驗證紀錄。
