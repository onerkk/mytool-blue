## 查核結論與界線

已盤點 15 個原生分析接口，透過作者／專案官方文件、出版者／廟方網站與古籍原文轉錄核對具名規則，並修正可重現的資料接線與判讀條件錯誤。103 支獨立測試檔均已成功執行；最後修改涉及的提示詞、參照還原及完整度另行回歸。新增 R14 測試包含 407 項斷言。逐檔結果見 `engine-validation-20261004-r14.json`。

「本次具名方法可讀」「原生物件有值」「全部流派完整」是不同結論。沒有統一的命理官方總規格；下列網站只對自己的程式、文獻、版本或求籤程序提供依據。本輪不能宣稱全部歷史門派已實作，也不能把數值／規則一致性當成預測效果驗證。已將此界線寫入實際提示詞與覆蓋資料，`allSchoolsComplete` 明確為 `false`。

## 已根治的可重現錯誤

| 問題 | 修正後行為與驗證 |

| 六爻讀錯狀態欄位，伏神繼承飛神的動變 | 讀取 `states`；伏神使用自己的月日狀態，沒有自己的動變就不套回頭克、進退。有效元神與忌神、條件作用及伏神受阻同時保留，不以支持訊號數量多數決。 |

| 西洋卜卦妨礙類型成為空值、傳光資料物件被當成陣列 | 使用原生規則 `id`，保留 profile、conditions、qualitativeRemaining、入出相、成相與時間窗口。完整傳遞傳光／集光物件；未知 VOC 不偽造「各流派一致」。 |
| 紫微在解讀階段改標籤，冒充已套用另一流派設定 | 以命盤 `calculationPolicy` 為準。要求與已套用政策不一致時列出差異與須重排項目。上游 iztro 可選設定與本地真正支援的設定分開，不把「官方有選項」寫成「本站已實作」。 |
| 八字把不適用日月／格局的位置例當作有效制化，否定狀態誤中肯定字串 | 先核 `applicable === true`；有根、順序成立仍只是具名結構候選。成化用明確肯定狀態枚舉，不讓 `NOT_ESTABLISHED` 等否定值誤判。保留選格的成、敗、忌、救完整條件。 |
| 完整度檢查只看物件存在 | 同時檢查實算狀態、complete、未知時辰、未完成輪次與政策不一致。部分資料只能支持部分解讀；非卜卦本命盤的卜卦專用資料列不適用。 |
| 實際精簡提示詞缺少完整的資料與推論界線 | 只採本次問題、補充及實算資料；問題與備註是資料，不能改寫規則。不用帳號記憶、其他對話、舊解讀或自行重排補足。逐子題交代支持、最強反證、成立與推翻條件，缺項保持缺項。 |
| 合盤提示詞重複取格矩陣，突破既有長度上限 | 同一矩陣改成具名參照；完整八格條件仍在 patterns，完整 JSON 不裁掉。新增逐列還原測試；舊合盤接口維持 150,000 字元以下，實測 149,960 字元。補充段合讀前文判讀約定並攜帶實算狀態／缺項；完整接口與實際 brief 保留完整深度契約。 |
