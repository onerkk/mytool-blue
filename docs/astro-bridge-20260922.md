# 綜合占星引擎整合 · 2026-09-22

> 本文保留前次修正紀錄。當前 `20260922audit2` 已處理過期測試並通過完整 `npm test`，快取為 `jy-main-v97`；最新修正、驗證及限制見 [全站覆查](full-audit-20260922.md)。

本補正納入 `fix.zip`。此 ZIP 包含前次特殊規則修正，只打包相對於 `gua.zip` 安裝後有變動或新增的檔案。保留目錄覆蓋；尚未代為部署。快取版本 `jy-main-v96`。

## 修正原因

舊綜合流程和獨立占星頁各自維護一組運算。綜合流程把出生時區固定為 UTC+8，且曾保留只覆寫星位的背景呼叫，衍生宮位與格局可能不同步。僅證明獨立引擎通過測試，不能證明所有呼叫端已使用該引擎。冷啟動時還有未等待依賴與遺失 Promise 的提交包裝，會提早繼續流程。

## 本次結果

- `JS/astro-bridge.js` 只協調同一組 `JYWestern`、`JYVedic` 原生引擎，不另寫天文公式或吉凶評分。兩盤共用原始民用出生時刻、出生地、IANA 歷史時區與同一觀察瞬間。
- 支援夏令時間缺口拒算及重複時刻前／後兩次選擇。真太陽時僅留在原本需要它的中國曆法路徑；選了第二次時刻時，對應 UTC 出生瞬間保持一致。
- 兩盤完成後原子提交；中途失敗清除舊盤。較新的送出或出生資料更改會取消舊請求，自動流程計時器不能覆寫新表單。重新送出可重試載入，不默默退回舊星曆。
- 綜合頁、完整資料匯出及 API 使用原生命盤。過時的相位吉凶計票、合成機率與占星交叉摘要不混入。舊畫面加強腳本遇到原生盤時交由新 renderer 顯示。
- API 保留結構化命盤；若 rawReadings 只是該 JSON 的相同字串副本，模型只收到一份。非重複的獨有資料仍保留。
- 時辰未知不固定上升、宮位、回歸盤、次限或確定交運日期；未知時刻涵蓋當地整日（包含 23／25 小時），中午只是有標示的星位參照。約略時刻保留敏感度範圍。
- 卡牌、六爻／易經及實物音效素材未更換。既有特殊規則補正在本 ZIP 保留，不需要另外疊上前一個 fix.zip。

## 驗證

`npm run test:astro-bridge`：7 組原生整合測試及 11 組 API 測試（API 上游使用測試替身，不呼叫付費模型）。整合測試載入真正的全部 `_buildPayload` 包裝，不是抽出幾行重寫一遍。檢查獨立與綜合資料相等、非 UTC+8 與歷史 DST、原始時鐘、畫面序列化、未知時辰、失敗清除與競態取消。

`npm run test:astro-bridge:browser`：真實 index、延遲載入、手動與自動提交、手機畫面、未知時辰重新送出與取消舊請求；沒有頁面例外。舊 western_upgrade、jyotish_full_upgrade 與 ephemeris-client 沒有再被綜合流程載入。可用 `JY_CHROMIUM` 指定 Chromium。

另回歸特殊規則 17 組、輸出一致性 9 組、卦象 11 組（含 4096 組爻值）、核心 10 組與曆法／引擎修正 9 組。西占／印度核心天文公式未在此橋接修正中重寫；沿用前次各 167 組 Swiss/Moshier 對照紀錄。完整 npm test 的既有舊提示詞字串及舊快取常數斷言問題仍見主修正紀錄，不宣稱全套通過。

## 來源與適用邊界

天文數值方法沿用專案內固定版本 Astronomy Engine 2.1.19 與已核對的 Delta T／ayanamsa 數值模型；參考 [Astronomy Engine 作者文件](https://github.com/cosinekitty/astronomy) 與 [Swiss Ephemeris 程式文件](https://www.astro.com/swisseph/swephprg.htm)。UTC、UT、TT 與民用時區不可混作同一時間標準。此次只改資料歸屬、入口與輸出，沒有以文案新增未驗證的天文算法。

格局與學理範圍仍以 `data/engine-rule-coverage.json` 及 `docs/engine-rules-20260922.md` 為準：完整 Shadbala、所有 Neechabhanga／Jaimini 分支等仍不是已實作能力。程式回歸檢驗的是已採用規則、數值與路徑的一致性，不是占卜預測準確率的實證。
