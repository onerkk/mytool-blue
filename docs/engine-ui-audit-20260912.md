# 靜月之光：引擎與介面查核紀錄

查核日期：2026-09-12。基準為本次提供的 `mytool-blue-master.zip`。

## 結論與查核範圍

找到並修正會影響年度、解讀標記及操作流程的程式錯誤。紫微主要安星結構在本次比較範圍內一致；不能由此推論所有日期、所有流派皆無誤，更不能把程式測試等同命理預測的科學驗證。

本次重點查核公農曆與節氣的時間基準、四柱及換日政策、起運與大運區間、紫微命身宮、五行局、星曜落宮、大限、年度與評分尺度。旺衰、喜忌及吉凶分數仍屬網站的規則與權重模型，沒有事件機率或實證準確率的含義。

## 已修正的問題

| 問題 | 原因與修正 |
|---|---|
| 八字流年立春界線 | 原函式把 UTC+8 節氣鐘面當成 UTC 瞬間，公共 API 的界線偏移八小時；另外部分呼叫端傳入命盤鐘面，形成混用。新增明確的 `instantTimestamp`，流年入口統一用實際瞬間，大運交集則先轉成相同命盤鐘面再比較。 |
| 八字月令與交節日數 | 月柱使用 lunar 引擎，交節日數卻另取舊分鐘表並使用瀏覽器本地 Date。改用同一引擎的前後「節」，以實際經過時間計日；驚蟄、芒種的簡繁名稱同步正規化。 |
| 起運前區間缺漏 | 未滿一歲或一歲起運時，舊條件可能不建立起運前區間。現在以出生至實際起運時間判斷；此列明示未另排小運干支。 |
| 閏日大運端點 | 二月二十九日加十年可能被 JavaScript 推到三月一日。改為非閏年取二月末日，並維持相鄰區間連續、前閉後開。 |
| 不合法輸入 | 日期、分鐘、秒、時區、參考日期及不支援的政策會拒算；避免 NaN 被 `|| 0` 悄悄改成有效時間。 |
| 紫微「不得」誤加分 | `/得\|利/` 也匹配「不得」。現在先辨識「不得／不得地／不」，再辨識正向級別；實際廟旺表的測試確認弱級低於平級。 |
| 紫微流年、流月分數偏移 | 宮位分析以 50 為中性，年度、月份的顯示門檻卻以 0 為中性；三方四正還會把年度基數再加至約 100。改為先移除各宮的中性基數，再套原有相對權重。中性測試輸入現在回傳 0。權重本身未經預測效果校準。 |
| 紫微年度與虛歲不同步 | 結果頁與提示詞曾直接使用公曆年份，農曆新年前可能與命盤政策相差一年。改為沿用命盤保存的農曆參考年度與虛歲，並標明「現行農曆年度」。 |
| 旬空、截空主副未區分 | 原本兩個地支都顯示同名空曜。保留雙支，依生年陰陽分成旬空／副旬、截空／副截，並將此口徑寫入 `calculationPolicy` 與提示詞。這是明示的版本選擇，不宣稱各派皆相同。 |
| 開鑰停止後無法滑動 | 選牌視窗尚未關閉就開啟儀式，儀式保存到舊的 `overflow: hidden`；儀式結束又將它恢復。改為先結束選牌視窗生命週期，再啟動儀式。沒有在結果頁強制清除所有視窗鎖。 |
| 開鑰啟動失敗後重試 | 錯誤時保留選項、重建可取消的選牌視窗；反覆重試不累加關閉按鈕，也不保留已失效的取消函式。 |

立春回歸例：依內附 lunar-javascript 1.7.7 的節氣結果，`2026-02-03T20:01:00Z` 為乙巳年，`20:03:00Z` 已為丙午年。修正前公共流年函式在後者仍回傳乙巳。節氣資料的「秒」是數值解析度，不代表已證實天文誤差小於一秒。

## 文獻與口徑判斷

| 一手來源 | 用途與判斷 |
|---|---|
| [香港天文台：二十四節氣日期及時間](https://www.hko.gov.hk/tc/gts/astronomy/Solar_Term.htm)、[節氣說明](https://www.hko.gov.hk/tc/gts/time/24solarterms.htm) | 確認節氣以太陽黃經定義，天文台公布時間使用 UTC+8；因此鐘面值不能直接當 UTC 瞬間比較。 |
| [香港天文台：2026 公農曆對照](https://www.hko.gov.hk/tc/gts/time/calendar/text/files/T2026c.txt)、[2023](https://www.hko.gov.hk/tc/gts/time/calendar/text/files/T2023c.txt)、[2025](https://www.hko.gov.hk/tc/gts/time/calendar/text/files/T2025c.txt) | 對照農曆月首、閏月及新年。2026 正月初一為公曆 2 月 17 日，和 2 月 4 日立春是不同界線。原有 36 筆月首測試重新執行。 |
| [NOAA：General Solar Position Calculations](https://gml.noaa.gov/grad/solcalc/solareqns.PDF) | 核對真太陽時的均時差、經度與時區關係。此次保留既有真太陽時計算，測試同一出生瞬間在不同時區不改變年、月柱；並非逐秒驗證整個天文曆表。 |
| [lunar-javascript 作者實作](https://github.com/6tail/lunar-javascript/blob/master/lunar.js)、[作者 API](https://6tail.cn/calendar/api.html) | 核對 `EightChar` 換日選項、前後節及 `getYun(..., 2)` 的分鐘折算法。網站維持 1.7.7，起運沿用三日一年口徑；日、時柱按所選鐘面計算。 |
| [iztro 作者安星規則](https://iztro.com/learn/setup)、[設定說明](https://iztro.com/posts/config-n-plugin)、[安星實作](https://github.com/SylarLong/iztro/blob/main/src/star/location.ts) | 核對安命身、主星、輔星及空曜等規則；以獨立安裝的 iztro 2.5.8 比較。設定固定 `yearDivide=normal`、`dayDivide=current`、`algorithm=default`，閏月另測本月及十五日分界。 |
| [《三命通會・論三刑》原文](https://www.shidianguji.com/book/SK1610/chapter/1kf5v6ol1zcpx) | 原文同時記錄兩種「無恩／恃勢」命名，並引《三車一覽》的另一說。現有網站採其中一種，未將名稱不同誤判為排盤錯誤，也未任意交換。 |

保留並區分的政策：八字預設子初換日，可指定午夜換日；本站午夜模式定義日干、時干均到午夜才換，與某些軟體「晚子時時干用次日」不同。紫微預設農曆新年換年、午夜換日、閏月沿用本月，也保留閏月十五日後用次月的選項。紫微流月採斗君，月干另按五虎遁；這些設定不能與別派結果混套。

四個純金色拱形按鈕改為金屬雕框、深色琺瑯、寶石鑲嵌、陰影厚度與浮雕字；每柱分別有年／月／日／時圖紋和點亮狀態。Three.js 場景增加切面晶體、開放式金屬托座、光環與細珠，固定金屬合併繪製以控制額外負擔。保留動態切換、減少動態偏好、返回、跳過和鍵盤焦點；未新增命盤亂數或捏造四柱值。

## 套用與重跑

此 ZIP 是差異更新包。將檔案依相同相對路徑覆蓋到原專案根目錄；`JS/cinematic-stage.js` 已重新打包，可直接上傳，無須在正式站另裝 Three.js。`index.html` 及各即時載入入口已同步更新快取版本。
