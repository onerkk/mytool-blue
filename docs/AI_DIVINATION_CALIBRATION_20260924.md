# 命理引擎與提示詞再校正紀錄

**日期：2026-09-24**  
**範圍：14 種方法的共同提示詞、各法專用指引、提示詞同步流程，以及六爻納甲案例**

## 這次查到並修正的問題

1. **六爻月日生克容易被反讀。** 引擎中的 `monthRelation`／`dayRelation` 是「月令或日辰作為來源」與爻的五行關係；例如「受克」表示來源被爻克，不是爻被克。原提示詞只列「日辰對爻：受克」，我先前也曾因此把方向看反。現在盤面和 JSON 判讀資料會直接寫「月令克爻」「爻克日辰」等方向，並要求分別比較每個用神候選。
2. **三合入口規則與《增刪卜易》不一致。** 舊引擎要求至少兩爻明／暗動才把完整三支列為成局入口；《增刪卜易》三合章明載「一爻動而合局」，另列兩爻動一爻不動的情況，也說空、破須待填／出月。現在改為三支俱全且至少一爻明動或暗動時列動局候選；三支皆靜標為靜態背景，成局仍保留空破條件，也不直接宣告化氣。
3. **API 用的十四法指引快照不會隨來源更新。** 全站同步腳本會更新閱讀語氣，但過去漏掉 `functions/api/ai.js` 的 `SYSTEM_METHODS` 快照。測試因此抓到六爻新指引未進入 API 系統提示。同步腳本現在一起生成並檢查這份快照。
4. **共用答題規則對深度的檢核不足。** 14 種方法都增加「先掃完整有效資料、找最強支持與牽制、把證據接回原問題、同一訊號對不同角色分開判、證據相持就降低確定度」的共用要求。六爻另要求逐候選看 `influences.network`，明說同一動爻可能扶應而克世；不把變爻擴寫成他人心念。親密關係題不以卦象推定未明示者的同意。

## 六爻實例回歸

使用者提供的資料已直接進入測試：2026-09-24 01:35:27、UTC+8、辛丑日／酉月、六次值 `7、9、8、8、8、6`，問「現任近期會願意跟我3p嗎？再找一個她認識的女性」。測試核對引擎得到地澤臨之山雷頤、二與上爻動；世爻標示「月令克爻、爻克日辰」，月日方向不再含糊。

上爻酉金對世爻卯木為忌神、對應爻亥水為元神；回歸要求提示詞把這種雙向差異各自列出。巳酉丑三支俱全但巳旬空，只有上爻動，因此結果保留為「有條件的三合候選」，不能寫成已成局或成功保證。第三位女性的意願沒有獨立盤面資料，不得把世應硬分配給她，也不得替任何人推定同意。

規則參照：[《增刪卜易》三合章](https://zh.wikisource.org/zh-hant/%E5%A2%9E%E5%88%AA%E5%8D%9C%E6%98%93/19)、[《增刪卜易》動變章](https://zh.wikisource.org/zh-hant/%E5%A2%9E%E5%88%AA%E5%8D%9C%E6%98%93/15)。本次線上核對的原文包括：三支三合的四種方式、一爻動而合局、空破待填／出月，以及變爻只作用本位動爻的規則。古籍用來核對傳統方法規則，不等於證明其事件預測有效。

## 測試範圍與限制

- 14 種方法共用答案契約及各自方法指引：檢查直接回答、證據與反證、方法原生結構、行動／限制，以及提示詞是否實際送入建構器和 API 快照。
- 本機全套 `npm test`：2026-09-24 執行完成，結束碼 0；包括引擎算例、曆法邊界、牌陣幾何、完整輸出資料及提示詞同步。這些是可重現的程式與資料契約測試，不是人工或外部模型準確率評分。
- 六爻新增案例：使用完整日期、硬幣紀錄和原題重建盤，逐項核對方向、世應差異、三合空爻條件及提示詞內容。
- Playwright 行動瀏覽器測試未執行：環境沒有 Chromium 可執行檔，測試在啟動瀏覽器前停止；不把它計作通過。
- **未宣稱已逐一測得 ChatGPT、Claude、Gemini 或其他外部模型的實際回答。** 網站的提示詞會交由使用者選擇的模型；本機測試不能證明模型會完全遵守提示詞，也不能證明占卜預測準確。這次能確認並修好的是排盤事實、規則提示、提示詞版本傳遞及已測案例。

後續要驗證「回答是否真的深入／準」，需固定各外部模型與版本，用預先登記且不洩漏結果的多法案例，盲評是否引用正確事實、涵蓋最強反證、回答原問與提出可驗證條件；若測預測準確，還要在事件發生後對所有命中與落空採用同一評分規則。
