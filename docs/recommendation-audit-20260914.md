# 全站選品提示詞與引擎檢查 — 2026-09-14

本次把「解讀後直接放賣場連結」改為完整的個人選品流程。正常有效的解讀須先回答原問題，接著給有理由的材料／品類主推薦，最後才自然邀請到靜月之光蝦皮賣場。這份更新以先前 `jy-main-v83` 為基準；本輪快取版本為 `jy-main-v84`。

## 修正的問題

1. 印度占星原本寫「需要時」才推薦，西洋占星另用一份簡略結尾；兩者與其他系統的共用規則分離。現在共用 `JS/reading-quality.js` 的選品流程，並各自取得相應方法的取用依據。
2. 原規則未明確區分經營商品與個人配戴。現在先回答生意選項，再另以提問者的命盤／問題需要與佩戴條件選材；不能由「適合賣龍宮舍利」推出「本人該戴龍宮舍利」。
3. 八字、合盤、人格卡、純排盤先前共用同一選品段。現在各有資料範圍與對象，合盤分清 A／B，不把兩人的喜用或對方的元素混成一份處方。
4. 印度占星下載的 JSON 沒有提示詞。現在與西洋占星一致，下載包含當次命盤、問題、方向及完整提示詞；實際瀏覽器檢查確認與複製內容一致。
5. 共用腳本缺失或瀏覽器仍持有舊版時，原備援文字可能退回「可省略推薦」版本。新增生成腳本，把各出口的備援內容與共用規則同步；對舊 v3 腳本也有相容檢查。
6. 瀏覽器檢查發現舊分享背景預載指向三張不存在的 PNG，已改接專案內現有的品牌背景。

## 實際的選擇邏輯

**本題的有效證據 → 提問者需要做的事 → 比較不同材料與佩戴條件 → 選一個主推薦、說清理由和使用方式 → 承接邀請 → 賣場連結 → 祝福。**

通常以三至五句完成選品段。原題就是配戴選擇時，應充分分析取用、主輔與替代條件，結尾承接已有結論，不再另推一套。缺少尺寸、預算或偏好時先推薦到資料支持的材料／品類層級，說明會改變選擇的條件，不因此只剩賣場連結。

「適合」要說明適合在哪一層：本題的行動需要、本人已知偏好、物性與使用環境、或明示的傳統象徵。材料選擇不能反過來改寫命盤；未實現的銷售、感情或健康結果不能當作已被證實的材料功效。

## 材料查核與適用條件

| 類別 | 本輪寫入的依據與取捨 |
| --- | --- |
| 水晶、碧璽、月光石、玉 | 把外觀／象徵與物性分開。月光石較怕碰撞；碧璽硬度不能當成抗摔保證；玉的韌性與具體工藝可納入日常佩戴比較。材料表是知識參考，並非固定推薦名單或庫存。 |
| 天鐵 | 先區分有鑑別依據的鐵隕石與藏式托查等名稱。鐵隕石的鐵鎳組成不能直接套到每件名為天鐵的商品；已知鎳接觸問題會改變選擇。 |
| 龍宮舍利 | 本次未提供具體實物鑑別與來源資料，因此保留名稱、文化認同與使用目的的條件；不填入未確認的組成、硬度、產地、增生或功效。認同相關文化、能核對實物資料且願將其配合既有修持時，可以是有理由的選項。 |

沒有加入依問題關鍵字、五行最低百分比或商品價格自動排名的選石演算法。複製提示詞與 API 的選品指引不附庫存候選。佩戴偏好不明時用明說的條件式推薦；財務困難先用已有物品，使用者拒絕選品時尊重其意願。

## 維護方式

此 ZIP 是本輪變更檔，適用於已含印度／西洋占星及分享卡更新的 `jy-main-v83` 專案。解壓後依原路徑覆蓋網站根目錄；保留 `JS/`、`functions/`、`scripts/` 等目錄結構。`CHANGE-MANIFEST.json` 列出每個新增／修改檔案及 SHA-256，無須刪除其他既有檔案。

調整選品規則後執行 `npm run sync:recommendations`，再執行 `npm run test:recommendations`。生成腳本同步備援文字、Pages Function 的選品規則與專案既有根目錄／JS 雙份檔，避免下次只改到其中一份。

`functions/api/ai.js` 是專案中的 Pages 備用端點。站內舊 API 入口仍有指向外部 Worker 的設定；本次更新了前端送出的規則及可取得的 Pages 原始碼，沒有存取或部署未提供原始碼的外部 Worker。複製提示詞與本地 JSON 匯出已在瀏覽器實測，無須該 Worker 才能使用。
